## Scope

Phase 12 was the **cohort substantiation + modal-axis** layer. The Phase 11 e2e demonstration that closed the AI advisor surface surfaced five engineering gaps that Phase 12 was built to close, plus introduced the modal analysis-type the project had reserved as Phase-11-stub-only:

1. **Modal analysis-type was rubric-defined but not behavior-substantiated** (Phase 11 A carry-forward) — `ANALYSIS_TYPE_TUPLE` listed `"modal"` and the rubric weights existed, but no service module parsed a CalculiX modal `.dat` output, no Euler-Bernoulli cross-check existed, no advisor produced modal-specific concerns, and no test case exercised the modal end-to-end path. Phase 12 ships the full modal axis as substantiated evidence.
2. **`_score_convergence_axis` modal branch was Phase-11-promised, not tested** (Phase 11 A retro §1) — the dispatch existed in source but had no behavioral test. Slice A closes this with explicit raw_score + rationale pins per modal sub-branch.
3. **Cohort-side surfaces existed but ran on synthetic data only** (Phase 11 retro §3) — `/cohort-executive-summary`, `/cohort-anomalies`, `/cohort-trend-anomalies` were scaffolded but lacked the multi-snapshot time-series + the analysis-type-distinct candidate-case set needed to actually fire real anomalies. Phase 12 D delivers a 3-snapshot degradation arc that triggers z-score outlier (danger severity) + trend-slope (info-to-warn severity) alarms on observable conditions.
4. **Cohort dashboard had no defensive parser layer** — frontend dashboard consumed upstream client coercions (which default `unknown` → `regressed` for buckets, `unknown` → `info` for severities). A backend schema drift would silently coerce to the most-conservative existing value and the dashboard would mis-render an unknown bucket as a regressed-bucket. Slice E delivers a raw-JSON-fetch dashboard client with defensive parsers that explicitly land on `'unknown'`, surfacing schema drift instead of masking it.
5. **Phase 11 retro §4 permissive-status-range assertions** — `assert 400 <= code < 500` patterns let unintended status changes pass silently. Slice F adds 12 supplemental integration tests tightening these to exact-code contracts.

## What worked

1. **Modal axis introduced end-to-end in 3 slices (A→B→C), not 6**. By concentrating modal axis work in A (domain), B (rubric + advisor), C (candidate cases), the modal-specific complexity was contained and slices D-F could compose modal naturally with the pre-existing cohort plumbing. The "modal" analysis-type discriminator was already in `ANALYSIS_TYPE_TUPLE`; Phase 12 just substantiated it without growing the SSOT.
2. **Honest statistical posture in slice D**. The n=4 statistical ceiling (|z|max=√3≈1.73, cannot reach 2σ at small cohort sizes) was acknowledged directly: 2 synthetic filler cases lift the cohort to n=6, with the rationale documented in `FILLER_COHORT_CASES` docstring. We did NOT silently inflate the cohort by triplicating real cases; we explicitly declared synthetic fillers in a named tuple separate from `PHASE12_FIXTURE_CASES`.
3. **Slice E load-bearing X:-2 anti-gaming guard worked as designed**. Four independent test sites verify `defensiveBucket` / `defensiveSeverity` / `defensiveAlertKind` fall back to `'unknown'` not to `'regressed'` / `'danger'` / etc. The dashboard surfaces schema drift instead of masking it as "regressed-as-healthy" or "unknown-as-danger" — both of which would be false alarms or false reassurance.
4. **Honest engineering caveats in Journey 6**. The blueprint §3.D / §3.F wording implied "regressed bucket" + "alarm cleared". Reality: the bucket math lands at trust=84 → still nominally "healthy" by score alone; the 4-point recovery slope still tips negative. We asserted what the math actually delivers — `slope_after > slope_before` not `slope_after == 0`. Same posture for slice D: relaxed the "regressed bucket" assertion to "trust score visibly degraded" with explicit documentation of the bucket math vs blueprint aspiration.
5. **PV rubric weight inlines closed (Phase 11 retro §1 carry-forward)**. Slice A renamed the magic `15` and `10` to `WEIGHT_BALLISTIC_METRICS_PV` and `WEIGHT_CONVERGENCE_STABLE_PV` with docstrings. The methodology doc cites every named identifier. Future rebalances chase names, not comments.
6. **Schema-pin centralization**. The Phase 11 retro §4 "permissive status-range" carry-forward is partially addressed via slice F's 12 supplementals; the schema-pin SSOT discipline is fully addressed via the centralized parametrized test in `tests/test_schema_versions_stamping.py` which now covers all 4 schema constants (CASE_COMPLETENESS, CONVERGENCE_STUDY, ADVISOR_CRITIQUE, COHORT_SNAPSHOT_MANIFEST) — single SSOT, parametrized.
