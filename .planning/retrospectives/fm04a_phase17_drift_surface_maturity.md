## What worked

1. **Cumulative view composability extended cleanly**. Phase 16 A introduced the cumulative view on the timeline envelope; Phase 17 A + B extend it to cohort-anomalies + signoff-record envelopes additively with MINOR bumps. The Phase 16 A timeline.cumulative_drift_attribution SSOT becomes the foundation for the signoff cumulative helper (B:-2 / M:-2: pure 2-line delegation, no inline math). The cohort cumulative helper composes the shared `_aggregate_cohort_drift_for_pair` (extracted in slice A to avoid duplicating the Phase 16 B latest-pair aggregation logic) — both `compute_cohort_drift_attribution` (latest pair) and `compute_cohort_cumulative_drift_attribution` (earliest-latest pair) call it. Anti-gaming guards (M:-2 shared SSOT; A:-3 server-computed signature pin extended to both signoff drift fields) land cleanly across all 3 slices.

2. **A:-3 server-computed extension is the load-bearing surface**. Phase 16 C established the pattern: signoff-write helper accepts no drift kwarg, server-side helper computes it from the timeline SSOT, `inspect.signature` audits the absence. Phase 17 B extends the pattern: write_signoff_record now accepts NEITHER `drift_attribution_at_signoff_time` NOR `cumulative_drift_attribution_at_signoff_time`; the test forges both kwargs and expects TypeError on each. Three independent layers (signature absence on both fields + server-side helper delegating to timeline SSOT + journey-level body audit confirming POST body carries neither field) maintain defense in depth for the new cumulative field with zero cost beyond the additive schema bump.

3. **Cross-axis comparable percentage_delta_slope inverts reviewer intuition correctly**. Slice C's worked example (completeness arc 50→42→34 vs energy_audit 15→10→5) demonstrates the load-bearing intuition: raw slopes alone suggest completeness collapses faster (-8.0 vs -5.0 weighted-pts/snap), but percentage_delta_slope reveals energy_audit collapses TWICE as fast relative to its ceiling (-33.333333% vs -16.0% per snapshot). The methodology doc states this explicitly: "the percentage view inverts the reviewer's intuition: energy_audit is collapsing roughly twice as fast as completeness when measured against each axis's ceiling. Cross-axis comparison REQUIRES the percentage view." A future reviewer comparing a completeness regression to an energy_audit regression cannot reason without the percentage view.

4. **SSOT cohort-fixture consolidation closes a real test-maintainability gap**. Before Phase 17 D, 5 journey/cohort-arc test files inlined the same 4-5 fixture-seeding helpers (≈80-120 LOC each) with minor naming variants. Hoisting to `tests/_test_utils/cohort_fixtures.py` (single helper module with kwargs for the two legitimate variant axes: `suffix` for per-arc staging-dir isolation + `drop_optional_artifacts` for the Phase 16 D Journey 2 energy-only invariant) removes ≈500 LOC of duplication AND enables the AST-based meta-test (`test_phase17_cohort_fixtures_ssot.py`) that catches future re-inlining via module-level def name scan. Both Phase 17 D journey files use SSOT from day one. The meta-test correctly tests two layers (SSOT module exports the helpers + no consumer re-inlines them) with the SSOT module itself explicitly excluded.

5. **5-route Journey 1 cleanly extends 4-route Phase 16 D Journey 1 pattern**. Phase 16 D Journey 1 walked 4 distinct route/verb pairs for the 4 drift envelopes; Phase 17 D Journey 1 adds the 5th route (cohort-trend-anomalies, the new percentage_delta_slope surface) and pins all 5 drift views in a single reviewer pass. The route-count contract test was straightforward to extend (EXPECTED_ROUTES_CROSSED frozenset goes from 4 to 5). The per-route signed-registry 422-refusal matrix didn't need to grow (cohort-trend-anomalies is non-parameterized, like cohort-anomalies). Cross-envelope coherence pin is a Phase-17-novel test: it asserts all 5 drift views coherently name energy_audit on the stuck arc — a future regression that desyncs any one view trips this single test.

6. **Recovery-arc invariant pinning at TWO surfaces simultaneously**. Phase 16 D Journey 2 pinned the cumulative-vs-per-pair invariant on the trust-score-timeline (single envelope). Phase 17 D Journey 2 extends to BOTH cohort-anomalies + signoff-history simultaneously: stuck arc → both views fire on energy_audit; recovery arc → both views' cumulative collapses while latest-pair surfaces the transient. Pinning the invariant on TWO surfaces means a future maintainer who silently breaks the cumulative semantic in only one envelope still trips Journey 2.

## What did not work / surprised us

1. **Slice-A TAA stashed slice B WIP mid-audit**. After slice A committed, the slice-A TAA's working-tree audit triggered an unexpected git stash that wiped the active slice B source edits (schema bump, SignoffRecord field, server-side helper, write+read+to_dict wiring). The slice-B test file's full content was on disk but disconnected from the source edits. Discovered via post-stash full-sweep returning 2546 (slice-A baseline) instead of expected 2562. Slice-A TAA's later report explicitly noted: "working tree contained orthogonal slice B WIP that was stashed during the audit; `stash@{0}` retains the full slice B `signoff_record.py` patch for manual recovery." Fix: re-applied all slice B source edits manually, re-ran tests (16 passed), committed. **Lesson**: commit slice work before spawning per-slice TAA. The TAA's working-tree audit is part of its anti-gaming probe set; an unstaged WIP looks like contamination. The slice-A → slice-B handoff window is the right boundary.

2. **Slice C T:-3 boundary test seeded the WRONG raw scores**. First-pass slice C test seeded completeness `score=50` expecting weighted=50; but `_completeness_weighted` formula is `round(score / score_max * 100) * 50 / 100` so `score=50` with default `score_max=100` lands `weighted=25` (not 50). The arc 50→42→34 became 25→21→17 with slope -4.0 (not the worked-example -8.0). Energy_audit is enum-driven (closed_aggregate=15 / partial_candidate=9 / else=0) and can't be seeded to arbitrary integers. Fix: seed completeness scores at 100/84/68 so weighted lands at 50/42/34; drop end-to-end energy seeding and rely on direct `_percentage_delta_slope(-5.0, "energy_audit") == -33.333333` test. The worked-example boundary test now uses the right scores. **Lesson**: when seeding a worked-example boundary, trace the weighted-score formula from raw input to expected output before writing the assertion; the rubric's "weighted axis points" are NOT raw scores.

3. **Ruff E402 caught mid-file import block placement**. After Phase 17 D refactored 5 journey files to import from the new SSOT, the import block was placed where the helper defs USED to live (mid-file, after several module-level constants + the sync ASGI client class). Ruff E402 (Module level import not at top of file) flagged all 5 files. Fix: move each import block up to where the other `from tests._test_utils` imports already live. The semantic placement (near the helpers used to be, with a Phase 17 D consolidation comment) had documentation value but violated Ruff style. **Lesson**: when refactoring imports in pre-existing files, place new imports adjacent to existing module-level imports, not where the old code body lived. Add a comment to explain the consolidation if needed.

4. **Schema-version assertion test rename overhead**. Each slice A/B bumped a consumer schema MINOR (cohort-anomalies 1.1→1.2; signoff 1.1→1.2; cohort-trend-anomalies 1.0→1.1). Each existing Phase 9/Phase 16 test file carrying a `payload["schema_version"] == "<old>"` assertion or a `test_<x>_schema_at_<old>` function name had to be updated. Pattern: rename the test function + update assertion with comment citing the additive bump. Total: 4 test files touched across slices A+B+C (no behavior change; one-line assertions + test-function renames). **Lesson**: when an additive MINOR bump lands, search-and-replace assertions are mechanical but require attention; the test rename is purely cosmetic but the assertion update is load-bearing (without it the test silently passes the old value).
