## What worked

1. **Carry-forward closure scoped tightly per slice**. Each Phase 13 slice closes EXACTLY one named carry-forward (Phase 11 §5 in A; Phase 11 §4 in B; Phase 12 §4 in C; Phase 12 §3 in D). No scope creep into adjacent surfaces; no mid-arc re-plan. The Phase 13 blueprint at `.planning/FM-04A_PHASE13_BLUEPRINT.md` named the closures explicitly and the per-slice sub-rubrics gated against widening.
2. **Slice-A `refused_claims` contract evolution from raise → filter**. The Phase 11 anti-gaming guard "raise on forbidden token in content" pivoted to "filter into refused_claims marker", which is a STRICTLY STRONGER guarantee (content never reaches the rendered surface) — not a relaxation. The deadlock-avoidance haystack exclusion is correctly scoped via single-key dict comprehension; the envelope-level audit remains as defense in depth (A:-3) on metadata fields the per-section filter doesn't traverse.
3. **Slice-B meta-test as drift guard**. The new `tests/test_phase13_status_code_discipline.py` is a TEST-SUITE-CONTRACT enforcement that scans every `tests/test_*.py` for 5 permissive patterns and pins the count to 0. A future test that re-introduces a permissive range trips the ceiling with the offending filename + line number in the error message. This pattern is reusable: the meta-test approach generalizes to other test-discipline pins (e.g., "no `time.sleep` outside designated retry harnesses", "no real-solver invocations outside `tests/test_*_e2e.py`").
4. **Slice-C honest fixture authoring**. The collapsed case's failure modes are ASSERTED via independent test assertions (not just trusted from the fixture file): `ratio_P_m_over_S_m >= 1.0`, `max_rel_err_*_pct > 5%`, `energy_audit.status == "unavailable"`, `mesh_sweep.candidate_stability == "candidate_observed_unstable"`. The TAA verified the regressed-bucket fire on live ASGI (`regressed_count = 1` with collapsed case trust = 45, well below the 50-bucket-edge). The fixture's `expected_results.json` carries an explicit `fixture_authoring_notes` block making the synthetic construction transparent — NOT a physics claim.
5. **Slice-D bootstrap discipline**. The HF1.8 self-protection clause requires every modification to `scripts/hf1_path_guard.py` to come through a PR with explicit AR/ADR cover. Slice D's modification IS the AR-2026-05-16-001 amendment-cycle ratification; the commit message names the AR id, the override env-var carries the bootstrap reason, ADR-011 is amended in the same commit. The defense-in-depth check (`_SIGNED_REGISTRY_RE` fullmatch-anchored so `GS-NNN-candidate` does not pass the carve-out helper) is pinned by a dedicated test. The audit log rolls over per the documented `reports/archive/hf_audit_window-NNN.md` protocol.
6. **Slice-A TAA HIGH + MEDIUM closed inline within slice B**. The Phase 13 protocol does NOT defer findings to a separate fix-up phase; slice B carry-forward closure work absorbed the slice-A TAA HIGH (frontend close-set suffix validation) + MEDIUM (first-token-wins single-winner pin). The slice-A re-verification stayed in slice B's commit rather than spawning a separate slice. Phase 12 did this too (slice H gap-close pass before FINAL TAA); Phase 13 does it in-arc per slice. Slice-D TAA's MEDIUM-1 (doc-vs-code inconsistency) similarly closed inline within slice E rather than triggering a fresh slice — the helper's `_SIGNED_REGISTRY_PREFIX_RE` addition + 3 new tests pin the closure in the same arc.

## What did not work / surprised us

1. **Slice-A initial TAA score 59/63 (93.7%) under the 95% per-axis floor (T 13/15 = 86.7%, A 7/8 = 87.5%, V 7/8 = 87.5%)**. Three findings: HIGH on frontend `_parseRefusedClaims` prefix-only validation (smuggled-suffix injection vector); MEDIUM on first-token-wins test admitting two valid winners (non-deterministic pin); LOW on retrospective file not yet created. All HIGH+MEDIUM closed inline in slice B; LOW deferred to slice E per Phase 13 blueprint. The HIGH finding was a real engineering gap: the `_RefusedClaimsSection` component deliberately doesn't apply `isAdvisorEntrySafe` (markers are reviewer-readable suppression records, not advisor copy), so a tampered `"refused: production ready for service deployment"` payload would have rendered verbatim. Close-set suffix validation closes the vector; the slice-B inline closure was the right scope, not a separate slice.
2. **Slice-C test_collapsed_trust_score_breakdown_shows_failure_axes initial failure**. The first version of the test asserted `breakdown_by_axis["convergence_stability"]["raw_score"] == 30` against the `/api/v1/trust-score/{case_id}` route — but that route reads from `project_state/graph_executor/<case>/...` not from the snapshot tree. The cohort-bucket trigger is driven by `/api/v1/trust-score-timeline/{case_id}` which reads from snapshots. Fixed by switching to the timeline route and pinning per-axis WEIGHTED values (not raw scores). Lesson: when authoring a fixture-driven test, always trace which route consumes the fixture before pinning the assertion shape.
3. **Slice-C HF1 path-guard trip on `golden_samples/*-candidate/` writes** (expected per Phase 12 retro §3). The commit was held + landed via `HF1_GUARD_OVERRIDE` with explicit per-commit reason citing the upcoming Phase 13 D AR-2026-05-16-001 amendment. The override path is the documented ADR-011 §HF1 Recovery flow; the alternative (swap slice C ↔ slice D order) was discarded because slice D needs slice C's fixture to verify its `test_candidate_carveout_allows_phase13c_collapsed_fixture` assertion in the after-state. The override-as-bootstrap pattern is the correct ordering.
4. **Slice-B meta-test docstring tracker initially missed multi-line docstrings**. The first version of `_scan_file_for_permissive` only skipped lines containing `"""` or `'''` — but the historical `status_code < 500` reference in `test_phase11_endpoints_integration.py:700` is INSIDE a multi-line docstring (between the opening and closing `"""`). Added a triple-quote state-tracker that handles both single- and double-triple-quote delimiters + same-line open-and-close. The lesson: a meta-test's static scan must mirror the Python tokenizer's state-tracking, not just line-by-line pattern match.
5. **Slice-D `test_zone_has_all_nine_categories` regression**. The existing test parsed `entry.rule.split(" — ", 1)[0]` and expected `{HF1.1, ..., HF1.9}`. The slice-D amendment renamed the HF1.7 entry's rule prefix to `HF1.7a` (HF1.7b lives in the helper, not the ZONE table). Updated the test to expect `HF1.7a` in the set with a docstring naming AR-2026-05-16-001. This is a legitimate amendment, not a regression; the test was correctly updated rather than the production code being patched to satisfy the test.
