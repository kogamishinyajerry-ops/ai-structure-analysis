## What worked

1. **Cross-route SSOT helper consolidation in slice A**. Before Phase 14 A, signed-registry refusal was inline-declared in three places (`_SIGNED_REGISTRY_RE` in advisor_critique.py + case_completeness.py + signoff_history.py) with three slightly-different detail strings. Slice A consolidated into one SSOT helper that 14 routes import. The meta-test's `_KNOWN_CASE_ID_ROUTES` SSOT tuple + `_OPT_OUT_ROUTES` opt-out list together make a new `/{case_id}` route addition trip a test failure (either schema-check on the introspected set OR per-route gate check) so future maintainers cannot silently route around the discipline. This is the classic "make the right thing easy and the wrong thing impossible" pattern.
2. **Analytical cross-check as substantiation, not just rubric weight**. Slice B's 1D-bar cross-check is a CLOSED-FORM physics pin (`c = sqrt(E/rho)`, `t = L/c`) — not an arbitrary tolerance band. Slice D's fixture is constructed to land within 0.97% of the analytical pin; the 5%-tolerance constant has 4× headroom for dispersion + finite-element discretization + contact stiffness softening. A fixture authoring error (wrong rho, wrong L, wrong frame_dt) trips the A:-3 test BEFORE downstream consumers can rely on the wrong analytical pin. This is the Phase 12 modal-cantilever pattern (Euler-Bernoulli `f_n = (k_n·L)² / (2π·L²) · sqrt(E·I/(rho·A))`) applied to the transient axis.
3. **4-theme advisor branch with theme-header anchor pattern**. Slice C's tests grep by theme-header (`contact stiffness convergence` not bare `contact stiffness`) so a maintainer who tries to satisfy the test by inserting a marker token into a different theme's body trips a different assertion. The theme-distinctness invariant is asserted explicitly: `len(set(all_strings)) == len(all_strings)` catches boilerplate copy across categories. Theme 4 cross-references slice-B `bar_wave_first_reflection_s` — strong inter-slice integration that the slice-C TAA flagged as a positive note.
4. **Slice-A REQUIRES_REWORK closure inline in the same arc**. The slice-A TAA returned 55/63 with HIGH-1 (visualization.py helper-call ordering) + HIGH-2 (advisor-critique + case-completeness stragglers still inlining the regex) + LOW-1 (candidate-passes single-anchor) + LOW-2 (missing methodology paragraph). All 4 closed in commit `5779fe7` within the same arc; re-audit independently confirmed 63/63 with one new LOW-3 (signoff POST still inlined) closed in `071a0f2`. This is the Phase 13 protocol: findings close inline, not in a separate fix-up phase. Slice-B LOW-1 (docstring drift) similarly closed in slice-C commit. The arc never reverted into a re-plan; the closure path was linear.
5. **Deterministic pure-Python generator for the slice-D fixture**. `gen_rod_wave_impact_deck.py` emits the fixture from SSOT constants with no random / no timestamp / no env-dependent input — running the generator twice produces byte-identical output. The autouse module-scope fixture in `test_phase14_rod_wave_impact_candidate.py` re-runs the generator if the gitignored route-readable copies are missing, so a fresh clone passes the slice-D tests without manual setup. This is the Phase 12 modal-cantilever generator pattern (deterministic + idempotent + present-file-checked).
6. **Helper-call ordering invariant pinned by methodology + by code-review-only check**. The methodology doc explicitly states "Helper-call ordering — MUST fire BEFORE any filesystem stat" with the visualization.py ordering miss documented as an instructive example. Since the meta-test can only verify the symptom (422 with canonical detail) and not the call-order (HF1.7a + HF1.7b prevent planting a signed-registry fixture on disk to verify the ordering directly), the documented invariant is the load-bearing audit. The slice-A TAA caught the original ordering miss precisely because it read the diff — not because a test failed.

## What did not work / surprised us

1. **Slice-A initial TAA score 55/63 (87%) under the per-axis floor on M (10/12) + T (14/15) + C (10/12) + V (8/8) but A (6/8 below 8/8 floor)**. Four findings: HIGH-1 visualization.py helper-call ordering (resolver ran before refusal, breaking A:-7 defense-in-depth); HIGH-2 advisor_critique + case_completeness stragglers (still inlining regex + hand-rolled detail strings, contradicting methodology); LOW-1 candidate-passes single-anchor route; LOW-2 missing methodology helper-call ordering paragraph. The rework was the largest single-slice closure of the arc — 5 file edits across 2 commits. **Lesson**: when consolidating an inline pattern across multiple modules, the SSOT migration MUST sweep ALL inline declarations in the same arc; partial migration is worse than no migration because the methodology doc's "shared SSOT" thesis becomes a lie that future maintainers cannot trust.
2. **Slice-B docstring + methodology cited `ANALYSIS_TYPE_TUPLE[3]` instead of `[2]`** (the tuple is `("ballistic", "linear_static_pv", "explicit_dynamics", "modal")` so `explicit_dynamics` lives at index 2). The TAA caught this immediately; the test correctly asserted `[2]` so no runtime bug, but documentation drift would have misled a future contributor relocating the constant. **Lesson**: when a docstring cites an index into another module's data structure, the index MUST be verified at write-time by running `python -c "from app.services... import ANALYSIS_TYPE_TUPLE; print(ANALYSIS_TYPE_TUPLE.index('explicit_dynamics'))"` rather than copying from blueprint text.
3. **Slice-C `test_contact_stiffness_theme_emitted_distinctly` initial failure (2 matches expected 1)**. The energy_partition theme's failure-mode enumeration mentions "contact stiffness too soft" as one of the non-physical-energy-injection causes — so a bare `"contact stiffness" in m.lower()` filter matched both the energy-partition theme AND the contact-stiffness theme. Fixed by matching the theme-header pattern `"contact stiffness convergence"` instead of the bare token. **Lesson**: theme-distinctness tests should ANCHOR on the theme header, not on the marker token alone, because adjacent themes legitimately reference each other in their bodies.
4. **Slice-D `status_reason` initial absent "not signed validation" wording**. The first version phrased the disclaimer as "...signed validation, benchmark agreement, and Tier 2 promotion are explicitly deferred" — which conveys the SAME semantic but the test asserted the exact tokens `"not signed validation"` + `"not benchmark agreement"`. Fixed by prefixing the status_reason with the explicit disclaimer trio. **Lesson**: when the cross-slice contract is "Tier 1 disclaimer trio MUST contain the literal `not signed validation` token", paraphrasing the disclaimer (even more naturally) breaks the contract. The literal token check is the right pin precisely because it forces consistency.
5. **`project_state/` gitignored means slice-D route-readable fixture copies cannot be checked in**. The first commit attempt errored on `git add project_state/...`. Fixed by adding an autouse module-scope fixture in `test_phase14_rod_wave_impact_candidate.py` that re-runs the generator if the route-readable copies are missing. **Lesson**: a fixture that spans both version-controlled and gitignored locations needs a regeneration hook in the test module so a fresh clone passes the tests; the generator script is the single source of truth, not the on-disk state of the gitignored copy.
